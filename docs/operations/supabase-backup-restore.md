# النسخ الاحتياطي والاستعادة — Supabase

هذا الإجراء يثبت قابلية استعادة مخطط التطبيق `public` في قاعدة PostgreSQL معزولة. لا يحل محل النسخ المدارة في Supabase أو الاستعادة الزمنية `PITR`، ولا يثبت أنهما مفعّلان.

## قواعد إلزامية

- لا تُنفذ الاستعادة فوق قاعدة الإنتاج أو أي قاعدة تحتوي بيانات حقيقية.
- قاعدة الوجهة يجب أن يكون اسمها بادئًا بـ `restore_drill_`، وأن تحمل تسمية تشغيلية تبدأ بـ `disposable-`.
- يجب اختلاف رابط المصدر عن رابط الوجهة.
- يمنع البرنامج استخدام مرجع مشروع الإنتاج `emzytxqkxjjhsivqxdiu` في رابط الوجهة.
- لا تُحفظ روابط قواعد البيانات أو كلمات المرور أو ملفات التفريغ في Git أو artifacts عامة.
- تشغيل الأداة يحتاج الإقرار الصريح `RESTORE_DRILL_ACK=DISPOSABLE_ONLY`.

## Preflight — قراءة فقط

1. افتح لوحة Supabase الرسمية وتحقق من تاريخ آخر نسخة ناجحة، مدة الاحتفاظ، وحالة PITR.
2. سجّل نقطة الاستعادة المستهدفة وRPO/RTO المتوقعين دون تغيير الإعدادات.
3. أنشئ قاعدة PostgreSQL مؤقتة مستقلة باسم يبدأ بـ `restore_drill_`، ولا تربطها بتطبيق الإنتاج.
4. جهّز رابط مصدر بصلاحية قراءة مناسبة ورابط وجهة مؤقتة بصلاحية الاستعادة.

إذا تعذر إثبات النسخة أو PITR، فالقرار `HOLD` حتى لو نجح الاختبار المنطقي المحلي.

## تشغيل الاختبار المعزول

```bash
RESTORE_DRILL_ACK=DISPOSABLE_ONLY \
RESTORE_TARGET_LABEL=disposable-quarterly-drill \
SOURCE_DATABASE_URL='postgresql://…' \
RESTORE_DATABASE_URL='postgresql://…/restore_drill_2026q3' \
bash scripts/local-db/backup-restore-drill.sh
```

تقوم الأداة بتفريغ مخطط `public` فقط بصيغة custom، واستعادته مع `--exit-on-error`، ثم مقارنة عدد الجداول العامة. النجاح يظهر كسطر يبدأ بـ `RESTORE_DRILL_PASS`.

## Post-verify

- تحقق من ظهور `RESTORE_DRILL_PASS` وعدم وجود أخطاء مخفية قبله.
- نفّذ اختبارات القراءة والصلاحيات الأساسية على الوجهة المؤقتة.
- سجّل وقت بدء التفريغ ونهاية الاستعادة لحساب RTO الفعلي.
- احذف قاعدة الاختبار المؤقتة من خلال إجراء منفصل ومعرّف دقيق بعد حفظ دليل النجاح؛ لا تضف حذفًا تلقائيًا إلى هذا البرنامج.

## بوابة القرار

- `PASS`: نسخة مدارة حديثة مثبتة، PITR مثبت حسب الخطة، واختبار الاستعادة المعزول ناجح.
- `PASS_WITH_NOTES`: الاختبار المنطقي ناجح، لكن PITR غير مطلوب أو غير مشمول بالخطة مع توثيق ذلك.
- `HOLD`: حالة النسخ/PITR غير مثبتة، أو لا توجد وجهة مؤقتة آمنة.
- `BLOCKED`: لا يوجد وصول رسمي إلى لوحة Supabase أو بيانات اتصال اختبارية.
